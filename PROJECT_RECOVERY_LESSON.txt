Recovery lesson and permanent development rule: The project had a known-good Cloudflare Worker baseline at commit 2dce82e25045520dd1eda303650d55968a31f138, where the Cloudflare smoke workflow actually executed its full validation path successfully. Subsequent changes introduced two different classes of failure that must never be conflated again. First, GitHub Actions began producing very fast failures with jobs containing no executed steps, so those failures were infrastructure/workflow-startup failures and were not proof that application code was broken; source code must not be changed merely to chase a red Actions badge when the runner never executed a test command. Second, the first proven runtime-contract regression was commit e1c5702, which added a hard AI_ENGINE_URL and AI_ENGINE_SHARED_SECRET preflight to paper-bot startup, changing the known-good behavior so the paper bot could not start when the external AI engine was not configured. Later changes compounded the problem by rewriting Worker routing, paper-cycle integration, dashboard components, and production entrypoints in overlapping commits, creating configuration and API-contract drift. During production recovery, an additional concrete Cloudflare RPC bug was identified: a DurableObjectStub is a remote client and does not expose the Durable Object instance's ctx/storage; production routing must never call stub.ctx.storage. Data owned by a Durable Object must be exposed through explicit public RPC methods or returned by an existing RPC method such as get_state(). This invalid stub context access caused protected dashboard routes to fail and the frontend to collapse multiple endpoint failures into the generic 'Failed to fetch dashboard data' message. The recovery rule is therefore: use 2dce82e as the historical runtime baseline; keep worker_entry_api.py as the single routing authority; keep worker_entry_live.py as a thin production adapter only; add FastAPI integration through AI_ENGINE_URL and AI_ENGINE_SHARED_SECRET without creating a second trading brain or execution path; keep paper trading independently gated by the Durable Object and BOT ON state; add new components one at a time and validate each boundary before adding the next; never duplicate routing, risk, execution, or exchange responsibilities; never access Durable Object internals through a stub; never rewrite a stable component for style alone; never treat GitHub Actions red as an application failure until a real workflow step has executed and produced an actionable error; and never silently change ARCHITECTURE.md. ARCHITECTURE.md may change only when the project owner explicitly authorizes an architectural change. The Cloudflare variables AI_ENGINE_URL and AI_ENGINE_SHARED_SECRET are intentionally runtime configuration and do not need to be placed in GitHub repository secrets merely for the application to connect in production; CI should only require those secrets when a workflow explicitly performs a real external FastAPI integration test. This document is a permanent warning against repeating the previous drift-and-patch cycle.
