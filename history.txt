PURPOSE
This file records the state of the system before the next risk/execution redesign. It is the audit checkpoint requested before implementation work begins.

1. INCIDENT OBSERVED
- The dashboard previously showed Cloudflare Worker errors such as: "A Worker script configured by the website owner threw an unhandled exception" and resource-limit termination.
- Paper History could show "No persisted cycles" / Supabase unavailable even though persisted paper-history data existed. The UI failure was therefore not equivalent to an empty database.
- The login path was also affected by browser-side dashboard polling and Worker pressure.

2. ROOT-CAUSE FINDINGS
- Durable Object paper scheduling was configured with CYCLE_INTERVAL_MS = 5,000 ms while market observation maintained up to 1,440 market points. Each observation merged, retained and persisted the market history and could call Supabase persistence.
- The Worker paper-control path imports the paper-cycle engine, making the runtime heavier than necessary for unrelated HTTP requests.
- The browser contained a dashboard status polling path that could run before authentication. This was changed so CycleUpdateToast only polls while authenticated and uses a 15-second interval.
- Existing GitHub CI failures recorded in the repository audit were runner/workflow initialization failures: recent jobs failed in roughly 3–9 seconds with steps=[] and BlobNotFound when logs were requested. Those failures did not prove that application compilation/tests had executed.

3. CURRENT CODE BASELINE
- Supabase remains the canonical source for persisted Paper History.
- Market data acquisition, Market Pulse construction and Agent data connections are treated as protected interfaces for the redesign.
- The paper account is backed by a Durable Object.
- Existing execution uses BUY/SELL/HOLD and a maximum of three open positions with a default 10% allocation.
- Existing execution did not provide a sufficiently realistic, configurable risk engine for stop loss, take profit, trailing protection, fees and slippage.
- Existing Paper History exposed large raw JSON blocks. This was technically useful but difficult for a human operator to read.
- The application renders PaperHistoryLibrary from App.jsx. The requested UI direction is one human-readable history library, not two competing history tables.

5. IMPLEMENTED REMEDIATION — 2026-09-01
- Added fronted/risk_engine.py as a separate deterministic risk layer. It does not fetch market data and does not alter Market Pulse or Agent connections.
- Added adaptive ATR stop loss, fixed-percentage stop loss, risk/reward take profit, ATR take profit, fixed-percentage take profit, trailing stop, break-even protection and optional maximum holding time.
- Default paper profile is BALANCED: ATR stop at 1.5x, 2R take profit, ATR trailing at 1.25x and break-even at 1R.
- Added execution friction: configurable fee rate and slippage in basis points. Default fee rate is 0.30% for the paper taker-style model; this is intentionally configurable because exchange all-in fees can change.
- Entry and exit fills now use adverse slippage. Fees are deducted from the paper account. Net realized PnL includes entry/exit fees and execution slippage.
- Protective exits are server-authoritative. A position can close on STOP_LOSS, TAKE_PROFIT, TRAILING_STOP, BREAK_EVEN or TIME_EXIT even if the next AI direction is HOLD.
- Protective exits are promoted to real SELL execution actions in the canonical execution ledger, while the AI candidate remains visible for forensic comparison.
- Added GET/POST risk settings endpoints under /api/dashboard/paper/risk and /api/dashboard/paper/settings.
- Changed Durable Object alarm cadence from 5 seconds to 60 seconds. This aligns observation/decision cadence with the 1-minute market view and materially reduces repeated CPU/storage work while preserving the existing 30-minute Market Pulse construction.
- Added richer performance metrics: gross profit/loss, fees, average win/loss, profit factor, win/loss count and open positions.
- Added a human-readable Paper History table. Raw JSON is no longer the primary presentation; details are available through an explicit Details action.
- Added a human-friendly AI Risk & Exit Profile with Conservative, Balanced and Aggressive presets.
- Added a richer Performance Snapshot that separates net PnL from win rate, fees and profit factor.
- Supabase history fetch path remains the same REST source and bounded pagination contract. Market data and Agent analysis contracts were preserved.

6. RESEARCH BASIS
- Fidelity's ATR reference describes ATR as a volatility measure, commonly using 14 periods, and specifically notes that ATR-based stops adapt to volatility; it gives 1.5x ATR as an example. Source: https://www.fidelity.com/learning-center/trading-investing/technical-analysis/technical-indicator-guide/atr
- Investor.gov's stop-order bulletin, updated August 18, 2026, explains that a stop price is a trigger and that a triggered stop order becomes a market order, so the execution price can differ from the stop price. Source: https://www.investor.gov/introduction-investing/general-resources/news-alerts/alerts-bulletins/investor-bulletins-15
- QuantConnect's current reality-modeling documentation recommends explicit fee, slippage and fill models because they materially affect backtest realism; it also notes that volatility can increase slippage. Sources: https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/key-concepts and https://www.quantconnect.com/docs/v2/writing-algorithms/reality-modeling/slippage/key-concepts
- Binance's current Spot API documentation distinguishes STOP_LOSS, STOP_LOSS_LIMIT, TAKE_PROFIT and TAKE_PROFIT_LIMIT and describes trigger behavior. Source: https://developers.binance.com/docs/binance-spot-api-docs/websocket-api/trading-requests
- INDODAX documentation confirms that market orders execute at available real-time market prices and incur trading fees. Its February 2026 CFX announcement states that the CFX component for IDR markets was adjusted to 0.0111% effective March 1, 2026; current all-in fee details should remain exchange-configurable rather than hard-coded. Sources: https://help.indodax.com/hc/id/articles/13348121502361-Apa-itu-Limit-Order-Market-Order-dan-Stop-Limit-Order and https://blog.indodax.com/penurunan-biaya-cfx
