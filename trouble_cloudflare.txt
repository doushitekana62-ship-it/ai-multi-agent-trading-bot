INCIDENT — 2026-09-02 — CLOUDFLARE DEPLOY REGRESSION AFTER ENTRYPOINT CHANGE
------------------------------------------------------------------------
The Cloudflare run supplied on 2026-09-02 began immediately after commit `d1e9a6c008b34278540d7f8d20a391908c0f8d7d` changed Wrangler `main` from the known-good `./worker_entry_api.py` to an experimental `./worker_entry_resilient.py` wrapper.

The supplied run successfully completed:
- build environment initialization
- repository checkout
- dependency installation
- Python package installation
- Vite production build
- Pywrangler environment creation
- Python package installation into the Worker environment
- Wrangler startup

The supplied log then ended inside the large `Attaching additional modules` table. That table is Python Worker packaging output and is not itself an error. The final Cloudflare error line was not included in the supplied log, so the exact remote failure cannot be asserted from that log alone.

However, the entrypoint change was unnecessary, immediately preceded the failed deployment, and violated the repository's documented known-good deployment contract. The smallest evidence-based correction was therefore to restore the canonical entrypoint rather than redesign the Worker.

FIX APPLIED
-----------
- Restored `fronted/wrangler.jsonc` main to `./worker_entry_api.py`.
- Removed the experimental `fronted/worker_entry_resilient.py` deployment entrypoint.
- Updated `tests/test_paper_scheduler_contract.py` so CI explicitly protects the canonical entrypoint.
- Durable Object alarm scheduling remains inside `PaperTradingState`; no Cloudflare Cron was added.

WHY THIS FIX
------------
The repository's own Cloudflare incident log identifies `worker_entry_api.py` as the deployment contract. The new wrapper was a speculative scheduler-recovery change, not a demonstrated deployment fix. Cloudflare Workers Builds deploys the Worker specified by the Wrangler configuration, so changing the entrypoint changes the packaged Worker surface. The correct response to an incomplete `Attaching additional modules` log is not to redesign the entrypoint.

PACKAGE MANAGER NOTE
--------------------
The supplied Cloudflare run shows Workers Builds automatically selected Bun 1.2.15 and created an ephemeral lockfile because no Bun lockfile was present. The historical deployment record warns against mixing package-manager resolution paths. This run nevertheless completed the Vite build successfully, so the current evidence does not justify changing the dependency graph. If dependency-resolution failure returns, first standardize the Workers Builds install configuration rather than changing application code.
