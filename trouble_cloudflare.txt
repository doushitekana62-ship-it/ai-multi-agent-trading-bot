Root-cause pattern
------------------
The recurring failure is an incoherent MUI v5 dependency graph. `@mui/material` declares compatible ranges for internal MUI packages, so a resolver can select a newer internal package while the public package remains pinned to 5.16.14. The resulting mixed MUI family causes missing/changed exports at compile time.

The previous `npm install --legacy-peer-deps && npm run build` path made this worse because Cloudflare first ran Bun dependency resolution and then npm performed another dependency-resolution phase. That two-manager build path is now considered unsafe for this repository.

Corrective strategy currently implemented
------------------------------------------
- Public MUI packages remain pinned to verified Cloudflare-compatible `5.16.14`:
  - `@mui/material`
  - `@mui/icons-material`
- The internal MUI packages are now ALSO declared as exact application dependencies at `5.16.14` as a deliberate defensive measure:
  - `@mui/core-downloads-tracker`
  - `@mui/private-theming`
  - `@mui/styled-engine`
  - `@mui/system`
  - `@mui/utils`
- The npm `overrides` block remains in place as a second safety layer for any npm tooling that may inspect the project.
- `fronted/scripts/verify-cloudflare-deps.js` performs a hard pre-build check. If any required MUI package is missing or is not exactly `5.16.14`, the build stops with a clear dependency-family error before React compilation.
- `build` has a `prebuild` hook that runs this verification automatically.
- `build:cloudflare` is `bun run build`.
- Cloudflare dashboard build command must remain `bun run build`.
- No deployment troubleshooting should use `npm install --legacy-peer-deps`.
- No `npm audit fix --force` during deployment troubleshooting.

Why the strict internal pins are intentional
----------------------------------------------
Earlier guidance preferred allowing MUI internals to resolve transitively. The repeated Cloudflare failures proved that this is not sufficiently deterministic in the target build environment. This project now prioritizes a reproducible Cloudflare build over a loose semver graph. The exact internal pins are therefore a preventive build-integrity measure, not an application-level API dependency design choice.

Validation order
----------------
1. Cloudflare performs `bun install`.
2. `bun run build` invokes the `prebuild` MUI-family verification.
3. React production build executes only if the MUI family is exact and complete.
4. Worker bundle/deployment proceeds only after the frontend build succeeds.
5. Worker health/API routes.
6. Durable Object PAPER_STATE binding.
7. FastAPI Cloud /health and /ready.
8. HTTPS AI engine connection.
9. Manual START PAPER BOT.
10. First paper cycle reaches FastAPI AI engine.
11. Agent/Orchestrator result is persisted.
12. Manual STOP PAPER BOT prevents further cycles.
