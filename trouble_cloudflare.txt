CLOUDFLARE DEPLOYMENT TROUBLE RECORD
====================================

Purpose
-------
This file records a recurring Cloudflare deployment regression. The same class of problem has happened twice. Do not repeat the same troubleshooting cycle by changing working architecture or dependencies without evidence.

Observed Cloudflare environment
-------------------------------
- Workers Builds detects Bun 1.2.15 and Node.js 24.18.0.
- Cloudflare automatically runs `bun install` before the configured build command.
- The configured build command was `npm install --legacy-peer-deps && npm run build`.
- This created two dependency-resolution phases: Bun first, then npm.

Incident timeline
-----------------
1. The frontend initially used MUI 5.18.x with some MUI subpackages resolved independently.
2. Build failed with:
   Attempted import error: '@mui/utils/chainPropTypes' does not contain a default export (imported as 'chainPropTypes').
3. MUI packages were repeatedly changed to 5.17.1, 5.15.14 and 5.14.20 while troubleshooting.
4. 5.14.20 was an invalid target for `@mui/icons-material` in the Cloudflare/Bun registry resolution used by this build. Cloudflare reported:
   No version matching "5.14.20" found for specifier "@mui/icons-material".
5. 5.15.14 installed successfully, but the subsequent npm build failed with:
   Attempted import error: 'elementAcceptingRef' is not exported from '@mui/utils'.
6. Therefore the real recurring problem is not simply "pick a lower MUI version". The dependency graph was being changed without keeping the package family and package manager behavior coherent.

Corrective strategy
-------------------
- Use the coherent MUI v5.18.0 package family. MUI currently identifies 5.18.0 as the `latest-v5` release line. Do not mix MUI minor versions across material, utils, system, private-theming, styled-engine and icons.
- Pin all MUI packages in `fronted/package.json` to the same 5.18.0 release family.
- Declare `packageManager: bun@1.2.15`.
- Add a `prebuild` hook that runs `bun install --no-save`, so even if Cloudflare invokes `npm run build`, the actual React build is refreshed against the same Bun-resolved dependency graph instead of relying on a second npm resolution.
- `build:cloudflare` is explicitly `bun run build` for environments where the build command can be controlled.
- Do not add dependency overrides as a workaround.

Why 5.14.20 is NOT the baseline
--------------------------------
A previous troubleshooting action incorrectly treated MUI 5.14.20 as a known-good universal baseline. The current Cloudflare log disproved that for `@mui/icons-material`: Bun could not resolve version 5.14.20. Do not restore that version merely because it is numerically older.

Cloudflare build configuration requirement
------------------------------------------
Preferred Cloudflare Workers Builds configuration:
- Root directory: `fronted`
- Build command: `bun run build`
- Deploy command remains the existing Python Workers deployment command.

If the Cloudflare dashboard still has `npm install --legacy-peer-deps && npm run build`, the repository now contains a defensive `prebuild` Bun synchronization step, but the dashboard setting should still be changed to `bun run build` to remove the duplicate package-manager phase entirely.

Architecture protection rules
-----------------------------
- Do not reintroduce an AI_ENGINE Cloudflare service binding.
- Do not move the CPython multi-agent Orchestrator into the Cloudflare Python Worker merely to simplify deployment.
- Do not replace real INDODAX market data with synthetic browser samples.
- Do not remove Durable Object manual ON/OFF paper-trading control.
- STOP must remain authoritative and must prevent future paper cycles.
- Real exchange execution remains locked during this development/reconnect phase.
- Do not add real exchange credentials during deployment troubleshooting.

Market Pulse requirement that must not be lost
----------------------------------------------
- Source remains real public INDODAX trades.
- Rolling window remains 30 minutes.
- One segment represents one minute.
- Any actual price change occurring inside a minute must be represented; it must not depend only on the browser's 5-second polling samples.
- No trade data for a minute is FLAT/GRAY.
- The market data must remain usable by the trading analysis/AI pipeline.

Dependency protection rules
---------------------------
- Keep the MUI family aligned and pinned.
- Do not infer that an older version is safer without verifying that every package in the family exists and is mutually compatible.
- Do not mix Bun installation and npm installation in the production build path when avoidable.
- Prefer one package manager for dependency resolution and build.
- Do not run `npm audit fix --force` during deployment troubleshooting.
