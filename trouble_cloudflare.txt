ROOT-CAUSE UPDATE
-----------------
There are two independent failure classes:

A. Resolver availability.
   Some manually selected MUI patch versions are unavailable to Cloudflare/Bun. Exact internal-package pinning is therefore unsafe.

B. CRA/Webpack module-export compatibility.
   Multiple valid MUI v5 installations reach production compilation and fail around `elementAcceptingRef` / `chainPropTypes` export resolution. Version rollback alone does not solve this.

The correct response is NOT another random MUI version change. The build must normalize the two problematic utility imports into CommonJS-compatible runtime resolution before CRA/Webpack analyzes them.

CURRENT CORRECTIVE STRATEGY — 2026-08-31 04:40+
-------------------------------------------------
1. Keep the public application baseline at:
   - `@mui/material`: 5.17.1
   - `@mui/icons-material`: 5.17.1

2. Do NOT force internal MUI packages to exact 5.17.1 versions. They must resolve from the official MUI dependency graph on MUI v5.

3. Keep the Cloudflare build path single-manager:
   Cloudflare `bun install` -> `bun run build`.
   Never run a second `npm install` during deployment.

4. `fronted/scripts/patch-mui-webpack-compat.js` now handles BOTH forms of problematic imports:
   - root named imports from `@mui/utils`
   - static default imports from `@mui/utils/elementAcceptingRef` and `@mui/utils/chainPropTypes`
   They are normalized to runtime `require()` resolution with `.default` fallback. This avoids the exact static default-export analysis failure observed at 04:39.

5. `fronted/scripts/verify-cloudflare-deps.js` now fails closed if either problematic static import form remains after patching.

6. The trading architecture is frozen while this frontend build problem is resolved.

WHY THIS CHANGE
---------------
The 04:39 build is the decisive evidence: dependency installation succeeded, the patch executed, and the validator passed, but Webpack still rejected a static default import from `@mui/utils/chainPropTypes`. Therefore the previous patch was targeting the wrong module boundary. The new patch removes static default-import semantics from both the root and direct-subpath forms and uses runtime CommonJS interop instead.

This remains a frontend build compatibility fix. It does not alter Market Pulse, paper-trading controls, AI-agent architecture, exchange execution, Durable Objects, or the CPython orchestrator.
